Context

Ad-tech

Combine attributes into a durable signal for advertising, analytics or cross-site recognition.

  • Commercial purpose
  • Consent-sensitive

Bot defense
Decide if
this is human.

Use the same signals to detect automation, payment fraud, account abuse or suspicious sessions.

  • Protective purpose
  • May be necessary
  • Service function

A detector identifies the technique, not its purpose. Counting every fingerprint as tracking therefore overstates the tracking category.

TrackMeasureLimits
Limitations

Scope and limitations

Supported here

  • Observed fingerprinting API patterns, storage writes and selected browser attributes in traffic.
  • Purpose estimates backed by vendors, Tracker Radar, hidden-vendor paths and context.
  • Paired changes after a consent state the crawler actually verified.
  • Replication across two crawls and a repeat-baseline noise floor.

Not established here

  • That every API use becomes a stable fingerprint or cross-site identifier.
  • A causal link from a fingerprint value to a particular identifier or ad bid.
  • A legal finding against any site; these are technical candidates for review.
  • Independent human ground truth for the annotation sample.

TrackMeasureConclusion
Conclusion

Consent gates many cookies.
It does not stop tracking fingerprinting.

Purpose changes interpretation.

Most fingerprinting is defensive. Purpose determines both the privacy meaning and the remedy.

Verified reject leaves 13/13.

A successful click is not a consent state. Confirm the stored state before comparing conditions.

Blocker runs also lose security.

They show the largest tracking reductions, with concurrent anti-fraud losses partly confounded by drift.
